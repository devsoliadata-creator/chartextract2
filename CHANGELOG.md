# Changelog

## 2026-10-05

- Fixed the master-table publish gate (`src/tools/table.py`): the current Agent 04 stage authority `agent04_inline_csv` is accepted (every run since the 2026-10-02 transport change had been marked `invalid_agent04` with zero rows). A failed Python hard check now keeps the table and flags review instead of discarding it. The points CSV contract is compared by major version instead of file bytes. Malformed legacy `line_sample` rows are dropped individually; the marker rows in the same table still publish. `aggregation_report.json` panels gain `final_flags` with the reason for any rejection.
- Made Agent 04 CSV validation non-fatal (`src/tools/qa_csv.py`, `src/workflow/steps/agent04_final_check.py`): invalid rows are recorded in `edit_audit.rejected_rows` instead of failing the panel; malformed report fields (verdict, series list, row_count, changes entries, unresolved_slots) are normalized and listed in `edit_audit.report_normalizations`. Any validation failure, not only omissions, triggers the single correction request, which now names the exact row errors. On the retry, Agent 03 rows are carried over unchanged for every candidate ID the reviewer omitted or returned invalidly (`carried_from_agent03=true` in notes, `edit_audit.carried_over`). The Agent 03 inventory fallback is reached only when nothing parses (for example a wrong CSV header). An unusable calibration object falls back to the Agent 03 calibration for any defect, not only a missing frame.
- Agent 04 now receives `panel.png` and `agent03/points.json` as Code Interpreter files (`runtime/agent04.yaml`); its prompt already required both.
- Added `src/tools/dense_ribbon.py`, a dense-region resolver that tracks each series' colour ribbon leftward from its clean markers, scores marker centres by ink excess plus glyph-template correlation, bounds the count by ink mass, and places the shortfall at the chart's visible pressure setpoints. Wired into `extract.extract()` (config `dense_ribbon_resolver`, on by default); the legacy column resolver `dense_region_resolver` is now off by default. Added points carry `source=dense_ribbon` with `evidence_kind=partial_marker` (shape-supported, `partially_visible_marker`) or `estimated` (`estimated_marker`), a native citation and `uncertainty_px`.
- Every stage's rows now carry an on-ink diagnostic: `stage_artifacts.build_candidate` checks that a 0.8 r disc around each row's native pixel carries its series colour; failing rows get `on_series_ink=false` in notes and are listed in `metadata.off_ink_rows`. Nothing is removed. Prompts for Agents 03 and 04 explain both new note keys.
- Python stage now prunes clearly mis-assigned detector rows (off their own series' colour and on another eligible series' colour); each drop is listed in `calibration.misassigned_row_pruning` (config `prune_misassigned_rows`). Ribbon rows are never pruned. On the saved fig2a runs this removes about 30 rows per panel that sat on neighbouring curves.
- Contract and documentation aligned with the resolver: `schemas/points_csv.contract.json` is version 4.2 with a `notes_keys` glossary and rules for `source=dense_ribbon`, `on_series_ink=false` and `carried_from_agent03=true`; `examples/points.example.csv` shows a ribbon-measured row, a ribbon-estimated row and a flagged row; Agents 02, 03 and 04 prompts and `workflow.yaml` role text describe the new note keys; hard checks report `off_ink_rows`, `dense_ribbon_rows` and `pruned_misassigned_rows`; README, workflow.md and docs/domain/files.md updated. A round-trip test proves resolver rows pass the Agent 04 validator unchanged.
- Tests for the resolver and the on-ink flag (`tests/test_dense_ribbon.py`).
- Added `tests/` with coverage for the publish gate and tolerant validation against the saved `combined_01/fig3a` panel.
